# 从选中组件生成状态原型 Implementation Plan

**Goal:** 批注单选组件后勾选“生成到新原型”，将截图及需求交给现有 AI 原型生成管线，创建独立的组件状态说明页。

**Architecture:** Commentary 单选工具捕获真实截图和受限 DOM 参考，经现有宿主桥接打开确认窗口。宿主用项目作用域创建独立原型目录，复用 prototype AI run；状态、错误和重试保留在宿主窗口。命名提示直接使用共享 naming-rules.json。

**Tech Stack:** React、TypeScript、Commentary、现有 ACP prototype runs、Vitest。

## 需求与交互

- [x] 单选组件时增加“生成到新原型”选项，默认不选；选择变化时重置，不污染普通修改路径。
- [x] 勾选后执行按钮显示“生成组件状态”，要求填写状态需求，当前选区截图供新页面参考。
- [x] 宿主确认页展示截图、新原型名称、状态要求与展示方式；默认同页平铺，可选交互切换。
- [x] 确认后创建独立目录，重试复用该目录，提供执行进度、错误与打开原型入口。
- [x] 提示词要求展示原始状态、指定的其他状态、触发条件与变化说明；未知业务规则明确待确认。
- [x] 新状态子标记使用共享命名表中的 component 作用域，避免复制原模块截图身份。

## Implementation Steps & Status

- [x] 在 common 定义并验证生成请求、构建状态页提示词。
- [x] 为创建原型增加受项目作用域约束的组件状态准备入口，保存来源截图及元信息。
- [x] 为 Commentary 增加单选捕获回调和新原型选项，透传 React／HTML 预览桥接。
- [x] 宿主增加确认／执行／重试／打开原型 UI，普通原型和参考页统一使用。
- [x] 复用现有 AI 原型生成任务，完成后刷新项目资源。
- [x] 构建 Commentary bundle 与管理端，更新开发服务。

## Testing Checklist

- [x] 验证请求字段、大小、选区失效、重复提交及未填写状态要求。
- [x] 勾选时不会走原页面的修改执行回调。
- [x] 未确认不创建目录、不调用 AI；失败重试复用目标目录。
- [x] 切换项目不会将旧任务结果写入新项目 UI。
- [x] 生成提示词同时包含真实截图、来源、状态要求、独立目标与共享命名规则。
- [x] API 临时目录测试、组件交互测试、服务端类型检查与构建。
- [x] 在独立浏览器中检查实际勾选和确认界面；不在真实用户项目触发付费 AI 任务。

## 验证记录

- 真实独立浏览器验证了勾选、要求输入、单组件截图和宿主确认；在确认前取消，没有在用户项目创建原型或执行 AI。
- 目视检查确认截图含 Header 内容；修复了带外边距／页面偏移的根节点在克隆画布中产生空白的问题。
- API 测试覆盖创建、规格可用、同任务幂等、冲突保护；会话测试覆盖重试、后台反馈与项目切换。
- 未调用真实 AI 验证生成质量；复用了既有 prototype AI run 管线，测试使用模拟执行结果。
- 服务端类型检查通过；管理端完整 TypeScript 检查仍有既存 vendor 未使用变量及 ES lib 配置问题，构建与定向回归独立验证。
