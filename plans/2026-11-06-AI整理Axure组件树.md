## 需求描述

在“复制可编辑原型到 Axure”的流程中增加 AI 整理步骤。AI 根据原型内容与布局理解业务区域，为元素自动命名、建立有意义的分组，生成便于继续编辑的组件树。整理后的结果沿用现有 Axure Bridge 复制与粘贴链路。

建议的子功能：

- 自动命名：如“提交按钮”“订单搜索框”，避免大量 div、span 等技术名称。
- 自动分组：如“顶部导航”“查询条件”“订单列表”“分页操作”。
- 树预览：展示整理前后结构，允许选择原始版本或整理版本后复制。
- 过程反馈：采集、AI 分析、校验、复制分阶段显示，可取消并重试。
- 设置与缓存：记住是否启用；同一导出快照可复用结果。

首版建议只覆盖管理端静态可编辑原型的主复制入口，不自动修改原型源码，不生成新的原型页面，不处理动态 Runtime 组件，也不承诺把普通 Group 转成 Axure Master、交互组件或动态面板。命名语言默认跟随页面内容，人工设置的业务名称优先保留。

后续需求关联：REQ-009 要求支持仅导出选中的元素，需要把整理管线复用到选择范围，不能因 AI 整理扩大到整页。REQ-008 要求全局 AI 生成/修改采用线框图风格；此处的结构整理保留导出快照的视觉数据，不额外重绘页面。

## 可行性结论与边界

技术上可行：复制前已经存在可处理的树结构，格式支持名称与嵌套容器，AI 调用基础设施也已具备。预计主要新增工作在数据摘要、结构校验、AI 任务和预览交互，而不是重做导出器。

尚未完成真实 Axure 验证。类型和转换代码支持 Group，不代表 Bridge 必然按预期生成原生分组；实际容器类型、嵌套坐标解释、粘贴后的样式及绘制顺序都应先验证。当前代码也没有保留每个输出图层对应的 DOM 来源信息，一个 DOM 节点可能产生背景、文字、描边和遮罩等多个输出节点，因此不能直接用 DOM 序号当作输出 ID。

## 方案比较

1. 仅打开 `preserveHierarchy`：成本低，但会保留大量实现容器，不能满足理解业务并整理树的目标。
2. AI 直接返回完整 Axure JSON：实现表面简单，但图片、路径、样式与结构易丢失，输出体积也大，不建议。
3. **推荐：AI 返回受限的重命名与分组方案，程序应用到原始快照。** 模型决定语义；程序负责保持图层、几何、遮罩、图片引用和协议字段。

推荐链路：

`采集当前可见原型快照 → 导出原始 payload → 生成节点摘要及可选截图 → AI 生成整理方案 → 本地校验与应用 → 树预览 → Axure Bridge 复制`

AI 输入包含快照内唯一节点 ID、现有名称、类型、文字摘要、矩形、父子关系、绘制序号；可附同一快照的截图帮助判断业务区域。截图与节点列表必须版本一致。先用 payload 中已有信息验证效果，再决定是否扩展 DOM role、组件元信息或 PRD 上下文。仅凭截图不能可靠识别每个图层 ID。

AI 只输出受 schema 限制的 `rename` 和 `group` 操作，引用本次快照内的 ID。图片 base64、SVG 完整路径、字体与全部样式不发送给模型。分组边界和协议字段由程序计算，不接受 AI 提供的坐标、样式或图片引用。

复用 ACP 的 provider/model 和运行基础设施，但使用专门的整理任务与响应解析；不能直接套用允许修改项目文件的原型生成流程。AI 结果按不可信数据校验，不执行返回的代码。

## 结构与视觉保护

- 所有原有图层恰好出现一次；原有 ID 保留，新建组 ID 独立生成，禁止循环、重复引用和无效引用。
- 首版只允许同一父级内连续的兄弟节点分组，嵌套分组也保持原绘制序列。不能为了目录美观按名称任意重排图层。
- 遮罩、SVG 内部、旋转/透明度/裁剪等特殊容器作为不可拆单元；不允许跨这些边界重挂节点。
- 不删除有视觉作用的包装节点，不修改文字、路径、图片引用、样式与交互数据。
- Group 的包围盒由程序计算。是否需要对子节点做坐标换算，以真实 Bridge 粘贴实验为准，不能只根据 JSON 的嵌套关系猜测。
- 限制名称长度、组数量、嵌套深度和单次节点数；复杂页面按安全区域分析，再整体校验。
- 单个非法操作不能部分污染原始 payload；先在副本上应用，完整校验成功后才成为可复制版本。

默认采集策略建议从 `preserveHierarchy: false` 开始，避免把每层 DOM 包装都传给 AI；已有必要遮罩或特殊容器仍必须保护。AI 整理与“保留 DOM 层级”应设计为明确的结构模式，避免两个开关叠加产生含糊行为。已有“保留原层级”导出继续保留。

## 交互、错误与性能

建议在现有导出区域增加“AI 整理组件树”选项。启用后，点击复制进入分析与前后树预览，用户确认后复制整理版本；同时保留“复制原始结构”。原始复制模式继续快速执行。

AI 任务有独立超时、取消和重试机制。取消后忽略迟到结果；项目、页面、预览或选项变化时使旧结果失效。模型失败、结果非法或超时，不声称整理成功，保留原始快照供用户直接复制。复制前重新检查 Bridge；失败可重试复制，不重复支付 AI 分析成本。

缓存键至少包括 payload/语义摘要哈希、整理规则版本、模型、语言和结构选项；当前导出 ID 每次生成，跨采集缓存需要规范化，首版可先只缓存本次快照。大页面通过摘要、分区和节点预算控制成本。延迟、费用和分组质量需要用真实样本测量，目前不承诺固定耗时。

## 首版实现与验证记录（2026-11-06）

已实现的入口包括管理端“复制可编辑原型到 Axure”，以及 React/HTML 预览中批注框的单元素 Axure 导出。所有 Make 入口都会先显示确认窗口。默认自动 AI 整理；旧偏好中明确关闭自动分析的设置仍保留，但会显示手动整理与复制原始结构的选择。自动 AI 模式采集时不保留 DOM 包装层，原始层级偏好本身仍保留。

实现文件：

- `src/common/axureTreeOrganization.ts`：摘要、严格操作 schema、引用/顺序校验及副本应用器；不传输 imageMap、完整样式或 SVG 路径。
- `src/server/managementApi.axureTreeOrganization.ts`：项目范围内的 `POST /api/axure/organize`，使用对话 AI 设置，独立任务、120 秒超时、600KB 请求上限。
- `src/index/domains/export/axureOrganizationSession.ts`：不可变快照、分析/复制状态、失败重试和迟到响应隔离。
- `src/index/domains/export/useAxureTreeOrganization.ts`：API 调用与 scope/iframe 生命周期。
- `src/index/components/dialogs/AxureTreeOrganizationDialog.tsx`：原始与整理后树预览，用户明确选择复制版本。

安全和兼容边界：

- 现有容器全部作为原子节点；首版不深入重组 SVG、遮罩或原有 Group 内部。新建 Group 可继续嵌套。
- 使用临时空工作区，显式请求 Codex `read-only` 或 Claude/OpenCode `plan` 模式；只有运行时报告支持该模式才调用，返回模式不符或存在运行时警告时拒绝结果。ACP 暂无公开的原子 prepare/验证模式 API，因此不将此机制宣称为独立的操作系统级沙箱。
- 取消和超时除中止 HTTP 请求外，还向同一 ACP thread 发送远端取消，最多重试三次。ACP/提供方不可用或未响应时，不能保证远端进程已经退出；本地会使迟到结果失效。
- 已精确兼容真实 ACP 将“技能描述因上下文预算缩短”的固定诊断文本放在 JSON 前的行为；其他前缀、解释或未知警告仍被拒绝。

## “没有效果”反馈后的入口修正

代码检查确认首版存在两条绕过路径：AI 开关默认关闭时主入口直接复制，以及批注框里的 Axure 按钮完全独立于主入口。已移除 Make 内部的静默绕过：

- 整页复制始终先打开窗口；关闭自动 AI 时进入 `captured` 阶段，可点击“AI 整理组件树”。
- 批注导出通过明确的 `onPrepareAxureExport` 能力及 `prepare-axure-export` 宿主消息进入同一窗口，不把一般宿主回调误认为支持 Axure 整理。
- React 和 HTML 预览均接入；没有 Make 宿主的独立导出保留原能力。
- 所有入口共用采集/会话锁，避免迟到的整页采集覆盖批注快照；双屏任一 iframe 重载或退出双屏都会使旧窗口失效。
- 新增入口、HTML 宿主通信、手动阶段、双屏失效和窗口操作验证。修正后 527 项测试、29 个测试文件通过；运行中的开发服务已重新加载，实际 HTTP 返回的主入口、React/HTML 预览及批注包均包含新流程。
