# 组件批注用途 Tab 与多条记录

日期：2026-11-08。
状态：已实现并验证，未提交；用户已确认直接清除旧格式组件批注。
功能分支：`codex/comment-purpose-tabs`。
分支基于 `codex/comment-list-and-toolbar` 的 `f7c5efc`：依赖该分支已经实现的批注列表、暂存和右侧工具栏。

## 新功能的需求描述

组件批注浮窗提供三个用途 Tab，按用户描述排列为「生成新原型」「修改原型」「引入说明」。每个 Tab 都有独立的 AI 指示输入和「暂存批注」「发送」操作，并可使用组件导出功能。移除原有「生成到新原型」复选框与头部「引入说明」执行入口，由当前 Tab 明确执行目的。

三个用途的草稿、暂存记录及执行反馈互相独立。同一组件可以拥有多条同用途或不同用途的批注；不能以组件 ID 或「组件 ID + 用途」作为批注的唯一身份。

### 已实现的子功能

- [x] 三个用途都有独立输入、暂存和发送；默认进入「修改原型」。
- [x] 切换 Tab、切换组件及关闭重开浮窗保留未提交草稿，按页面、组件、用途隔离；首版不承诺未暂存草稿刷新后恢复。
- [x] 新建态暂存成功后，把该条记录加入右侧列表，只清空当前用途已成功保存的草稿，并准备下一条批注。失败时保留内容和本次记录 ID。
- [x] 从列表显式点击「编辑」进入已有批注编辑态；暂存更新原记录，另有「新增批注」退出编辑态。定位组件与编辑批注是不同操作，避免误修改历史记录。
- [x] 右侧列表展示用途、组件名称、指示摘要与状态；支持全部及按用途筛选。相同组件的不同批注分别展示、勾选、编辑和删除。
- [x] 批量发送只允许同用途，混合选择时保留选择并提示按用途发送，不自动拆分或转换用途。
- [x] 「发送」沿用对应的现有流程：修改原型走 AI 修改；生成新原型走组件状态原型确认；引入说明走组件图文与目标 PRD 确认。发送不隐含授权绕过已有确认步骤。
- [x] 导出沿用截图中的组件导出（如 Axure），三个 Tab 均可使用；其作用对象仍是组件，不保存批注、不调用 AI、不清空输入。

## 现有实现与调整原因

1. `core/editor/state.ts` 中 `ElementEditMeta` 只有一份 `commentId`、`note`、`images`、`skillIds`，运行时通过 `editMetaByKey` 按组件存储。
2. `core/editor/lifecycle.ts` 的 `getCommentListEntries()` 使用 `meta.elementKey` 作为列表 ID，无法区分同组件多条批注。
3. `core/editor/persistence.ts` 的恢复流程通过组件获取同一个 meta，然后写入 `commentId` 和 `note`；仅在持久化数组里追加记录仍会在恢复时覆盖。
4. `core/editor/comment-batch.ts` 的修改操作传递 `Element[]`，再从组件读取当前内容，无法准确执行某一条历史批注。
5. 宿主 `previewActions.helpers.ts` 与 `useIndexPagePreviewActions.tsx` 有按 `elementKey` 去重的路径。新模型必须保留全部批注 ID 和内容，再单独归并组件定位、截图及组件锁。
6. 服务端 `managementApi.prototypeComments.ts` 已按批注 ID 合并与处理删除墓碑，可复用，但新增字段的往返、外部评审及并发保存仍需验证。

## 方案比较

| 方案 | 收益 | 限制 |
| --- | --- | --- |
| 给组件增加三份 note | 改动较少，能隔离三个输入框 | 同组件同用途仍只能一条；历史、状态和重试仍冲突 |
| 按用途建立三套独立存储 | 用途边界直接 | 重复持久化、附件及执行逻辑；合并列表复杂 |
| **统一批注记录集合，每条绑定用途** | 同组件可多条，统一恢复、列表、执行和导出入口 | 需要调整运行时身份、恢复及宿主桥接；推荐 |

## 数据与状态设计

新增 `ComponentCommentPurpose = 'generate-prototype' | 'modify-prototype' | 'document-component'`，与现有执行动作通过单一映射函数关联。

批注记录以 `commentId` 为主键，保存页面范围、组件身份与 locator、用途、指示、技能、附件、创建和更新时间。持久化仍优先复用现有 `PrototypeEditCommentEntry.id/comment/skillIds` 和独立 images 关系，扩展 `purpose`、`createdAt` 等必要字段，避免另建重复内容字段。

- 新增按 `commentId` 索引的记录集合，以及组件到批注 ID 集合的派生索引。组件交易 meta 继续管理文字、样式等实际编辑，不能把每条新批注恢复为一次文字或样式交易。
- 草稿通过 `(pageScope, elementKey, purpose)` 定位。草稿包含稳定的本次保存 ID、指示、技能、附件和可选 `editingCommentId`。暂存成功后结束该草稿生命周期，新条目生成新 ID。
- 每条记录的执行状态按 `commentId/requestId` 跟踪；组件锁继续按 `elementKey` 防止并发修改同一 DOM。状态与内容分别管理，不能用组件完成状态清除其他批注。
- 批次从选中的批注 ID 创建不可变内容快照。去重截图和目标组件时仍保留每条指示；同一组件多条修改按所选顺序编号组合为一次请求。
- 发送采用先保存快照、再进入原确认/执行流程。取消确认时保留暂存记录，不标为已执行；失败可重试同一条记录，不能重复创建。
- 保存期间切换 Tab 或组件时，异步结果只更新原草稿/记录；成功只清理已保存的草稿版本，不能清空用户随后输入的内容。

### 旧数据兼容

旧记录直接清除。

执行状态：用户已在会话中确认“直接清除即可”。普通组件批注加载时自动清理旧格式记录及其无引用附件文件，本地缓存同步清理；不提供迁移入口。服务端通过原子清理请求读取当前文档后更新，保留新用途记录、独立文字/样式交易、文字批注、语音及外部评审数据。文字/样式交易附带的旧批注内容会移除，实际交易保留。

## 浮窗与列表交互

浮窗结构：组件标题与辅助工具 → 三个用途 Tab（默认修改原型） → 当前用途的 AI 指示输入 → 当前用途说明与错误提示 → 导出、暂存批注、发送。导出位于底部公共操作区，所有 Tab 都可访问。

Tab 使用标准 tablist/tab/tabpanel 语义，支持键盘切换与明确的选中状态。三个面板共用布局组件，状态独立；Cmd/Ctrl+Enter 只发送当前 Tab，输入法组合期间不触发。发送按钮名称可统一为「发送」，通过旁边用途说明及确认窗口明确结果。

右侧全部视图的每条记录带用途标签，选择同用途批注后只显示对应的发送入口；不再为同一条批注同时展示「发送修改」「生成原型」「引入说明」三个可互换执行按钮。旧格式批注直接清除。生成与文档批次继续使用现有组合截图/确认行为，不在本轮扩大输出组织方式。

对同一组件的多条记录点击定位时使用同一个定位和高亮；选择、内容与执行状态仍各自独立。组件失效时记录可查看和编辑指示，但禁止执行，给出重新定位提示。

### 加载、失败与适配

恢复批注记录期间复用注入的 `PageSkeleton` 列表骨架；准备好或加载失败后移除骨架，失败显示重试，空列表显示创建引导。页面切换立即隔离原页面草稿与选择，防止显示或执行过期内容。本功能不新增 iframe；现有预览继续使用 `PreviewIframe`。

暂存、截图准备、发送、导出使用各自按钮进度与错误反馈，防重复点击。仅互相冲突的动作需要禁用，切换 Tab 不应丢输入。窄屏保证三个标签及操作按钮可触达；继承现有深色主题 token，尊重 reduced-motion，保留浮窗对右侧列表和工具栏的避让。
