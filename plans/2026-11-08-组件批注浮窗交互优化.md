# 组件批注浮窗交互优化

## 需求与设计

将组件批注浮窗整理为“来源与辅助工具 → 需求输入 → 输出位置与主操作”。使用现有中性表面与绿色强调色；桌面约 360px 宽，窄屏自适应。辅助操作不与主执行按钮争抢同一行，输入区域独立，输出选项移到输入框外。

## Implementation Steps & Status

- [x] 为普通组件批注增加独立底部操作区，保留引入说明、样式、导出、固定和关闭。
- [x] 将“生成到新原型”移至底部并解释目的；按钮随模式显示“发送修改”／“生成状态页”。
- [x] 优化尺寸、焦点、输入留白与主题适配；多选与执行中正确禁用，保留草稿。
- [x] 组件批注中 Cmd/Ctrl+Enter 执行当前主操作，输入法组合键不误发送，其他标注模式保留原快捷键行为。
- [x] 点击浮窗内部控件不意外提交批注，执行时仍由原流程按顺序保存。
- [x] 定向测试、真实隔离浏览器桌面／窄屏／主题检查，重新构建 Commentary 与应用。

## 验证重点

- [x] 主按钮清晰且不换行，辅助控件不挤压输入。
- [x] 新原型模式的单选约束、截图确认与禁用态保持有效。
- [x] 引入说明／导出／固定关闭仍可用，PRD 标注与外部评审不改变模式。
- [x] 不在真实项目执行 AI；操作加载继续用按钮反馈，不引入页面等待。

## 验证结果

- Commentary 源码与 ESM/CJS 构建、91 项定向测试通过。
- 隔离 Chromium 检查桌面、390px 窄屏与深色主题；新模式使用 Cmd+Enter 进入真实截图确认，取消后未创建原型或执行 AI。
- 复查补充了同一选区切换 PRD／外部／文本标注时清除并即时屏蔽新原型目的地，回归测试通过。
- 目标 TypeScript 检查仍报告仓库既有的 ES 库配置和 unused 错误；此次新增模块与函数没有新增类型错误。
